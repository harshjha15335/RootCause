# Root Cause contracts v0.3 — explanation pipeline

This revision follows the October 12 Role 3 explanation brief supplied for the October 20
review. Read this document and `.github/copilot-instructions.md` before changing contracts.
Team acceptance by the engine/UI owners remains necessary; these are proposed interfaces.

## Match event

`id`, `match_id`, `second`, `type` (pass/duel/cross/goal), `team` (home/away),
`player_id`, `ball` {x,y}, `players` [{player_id,team,position:{x,y}}]. Positions are metres
on a 105×68 pitch. Exactly 22 unique players, 11 per team. IDs contain 1–100 ASCII
letters/digits/underscore/hyphen. Times are integer elapsed seconds.

## Evidence package

`goal_id`, `match_id`, `source` (synthetic-fixture/debugger), `goal`, `links`, optional
`events` and `root_cause_evidence_id`. No player `views` are required or exposed.
Links contain `evidence_id`, `player_id`, `second`, `bug_type`, `description`,
`blame_percent`, `baseline_goals`, `fixed_goals`, `trials` (200).

Role 2 supplies attribution. Percentages sum to 100 and are never generated by a model.
Links are stably ranked by descending `(baseline_goals-fixed_goals)/trials`; ties preserve
the supplied order. The first ranked link is the root cause. A supplied root ID must
agree with this ranking. Event excerpts must be from the same match, have unique IDs,
and cannot occur after the goal. If excerpts are absent, Highlights uses chain links.
`get_events(from_second,to_second)` reads only these evidence excerpts, never raw match state.

## Explanation

See `samples/explanation.json` and Pydantic models in `api/contracts.py`:

- `goal_id`, `match_id`, `root_cause_evidence_id`, immutable `blame_order`.
- `status`: ready when the model Explainer completed, pending when cited templates are
  substituted or safety withheld prose. `source`: model/evidence-only. A pending
  explanation still contains factual template paragraphs, highlights and all attribution.
- `paragraphs`: one `{evidence_id,sentences}` per causal link.
- `root_summary`: cited sentences identifying the Debugger's first-ranked cause.
- `highlights`: `{evidence_id,start_second,end_second,caption}`. Each interval covers its
  link's real second, lies within the possession, and has a cited caption. The root is included.
- `recaps`: Fan, Analyst and Studio arrays of cited sentences.
- `warnings`, `latency_ms`.

Every sentence is `{text,evidence_ids,kind}`. `kind` is description, attribution,
counterfactual, root, or neutral. Every sentence has at least one supporting evidence ID.
Displayed text appends `[evidence-id]` to **each** sentence; there is no separate end-only
reference list. The Explainer assembles paragraphs from tool-supplied, audited factual sentences;
other models select structured plans. The server validates the actual returned prose. Unsupported prose and known IDs attached to unrelated facts fail validation.
This constrained rendering is deliberate; unrestricted model-written paragraphs are not accepted.

The graph is Orchestrator → (Explainer || Highlights) → Recap → (Fan || Analyst || Studio).
Recap receives completed paragraphs AND highlights. Its evidence-only tools are
`get_explanations(match_id)`/`get_patterns(match_id)`. Persona has no tools and can select
only the requested mode/detail from the cited story. Explainer gets one 15-second attempt
and one retry, subject to the graph's 20-second total deadline. If the deadline wins,
return a cited template with status=pending. Highlights failure uses the chain-link order;
other stages preserve factual story templates. Cancellation is propagated to model tasks.

## HTTP and WebSocket

| Method | Path | Behavior |
| --- | --- | --- |
| GET | /health | Process/configuration status |
| GET | /ready | Checks storage access |
| POST | /matches | JSON {seed: nonnegative integer}; starts seeded replay; 201 |
| GET | /matches/{id} | Metadata, status, score, goal IDs |
| GET | /goals/{id}/trace | Evidence package |
| GET | /goals/{id}/explanation?mode=fan&lang=en | Explanation, selected cited sentences and display text |
| GET | /goals/{id}/audio?mode=fan&lang=en | audio/mpeg; 503 when voice is unavailable |
| GET | /matches/{id}/report?mode=fan&lang=en | Full-time Bug Report; 409 until finished/all known goals processed |
| POST | /matches/{id}/finish | Declares full time for an externally streamed match |
| POST | /ingest/evidence | Accepts a recorded evidence package; 202; 409 on conflicting goal ID |
| WS | /live/{match_id} | Retained messages followed by live messages |

Modes: fan/analyst/studio. Languages: en/hi/es. Unsupported inputs return 422; missing
entities return 404. The explanation response adds `mode`, `lang`, `requested_lang`,
`sentences`, `text`, `translation_warning`, and `audio_available`. Translation covers
all prose fields and preserves citation IDs verbatim outside the translator. On failure,
return the complete original English record with lang=en and a warning; disable audio.
Audio speaks prose without reading machine IDs. Reports include goal summaries with
sentence citations, factual patterns, ranked top causes, and highlight order.

Messages are `{type,match_id,sequence,payload}`:

| type | payload |
| --- | --- |
| match.event | MatchEvent |
| goal.detected | {event_id} |
| trace.ready | Evidence |
| agent.step | {goal_id,agent,status, optional mode} |
| explanation.ready | Explanation (inspect status for pending templates) |
| match.failed | Generic pipeline failure message |

Sequences increase within a match. Clients deduplicate by match ID and sequence. Event
Hubs delivery is at least once; immutable event/goal IDs deduplicate processing. The demo
uses `{event:MatchEvent,evidence:Evidence|null}` envelopes; recorded evidence must match
the goal and retain source=synthetic-fixture. Raw events invoke the real Debugger plugin.

Azure routes except /health and /ready require Entra delegated API access. Browser sockets
use protocols ["rootcause",access_token]; native clients can send an Authorization header.
Never put tokens in URL queries. CORS permits FRONTEND_ORIGIN. Use one API replica/worker
until distributed stream fanout is implemented.

## Migration from the courtroom prototype

This is an intentional breaking contract change: `/verdict`, `verdict.ready`, player
views/testimonies and judge rulings are removed. Consumers must use `/explanation` and
`explanation.ready`; new results use the Cosmos `explanations` container. Bicep adds the
new container without deleting an existing legacy `verdicts` container. Old trace records
with the removed views field need explicit conversion before replay; no live production
migration was performed. Update the UI and engine together against these samples.
